# 网页评测控制台的依赖（设计 §8.1：独立的 .venv-web）。
#
# 与 requirements.txt（评测 harness 端）分开的原因：
#   - 控制台进程只需要 streamlit / altair / pandas / pyyaml 这一族；
#   - harness 侧需要 jieba / nltk / httpx，而控制台**不导入**它们（设计 §4.6
#     的依赖边界）。混装会让"控制台有没有误 import scoring"这件事从依赖层面
#     就无法验证。
#
# 装法（两端不同，勿照抄）：
#   服务器（部署目标，Linux）：系统 python3 既无 ensurepip 也无 pip，`python -m venv`
#     在该机器上直接失败。用仓库同款的 uv，并显式指定系统解释器：
#       ~/.local/bin/uv venv --python /usr/bin/python3.14 --seed .venv-web
#       ~/.local/bin/uv pip install --python .venv-web/bin/python -r requirements-web.txt
#   本机（Windows，自测）：
#       python -m venv .venv-web
#       .venv-web\Scripts\pip install -r requirements-web.txt
#
# 解释器版本要求 >= 3.12：numpy==2.5.3 的 requires-python 即为 >=3.12，
# 因此 uv 管理的 CPython 3.11.16 不满足这套钉版（实测解析失败）。
# 服务器实测组合为系统 CPython 3.14.4，安装日志只有 `+ 包名==版本` 行，未触发源码构建。
#
# 全部版本为实测可用的组合，由已安装环境的依赖闭包导出。下面的分组标出每一项
# 是被谁引入的，升级时据此判断影响面。
